# Technical Writing

Use these rules in addition to the general prose style when writing or editing technical documentation.

- Write for an engineering peer with the relevant domain knowledge. Define project-specific terms and unstated prerequisites.
- State prerequisites before the procedures that depend on them.
- Distinguish requirements from recommendations.
- Preserve exact identifiers, commands, paths, configuration keys, and error messages.
- Explain constraints and tradeoffs that affect implementation decisions.
- Use numbered steps when order matters and state the observable completion condition.
- Omit apologies and summaries that merely repeat visible changes.
